Issue #211: Android QA procedure (artifact page)

A page on claude.ai you run on the Pixel (and open on the laptop). State lives in the artifact's shared database, so ticks, results and notes survive a reload and show up on the other device. Same colors and fonts as the app so it feels like part of RepBunny. On a laptop the page widens to a list on the left and the open test case on the right; the phone layout below is the one that has to work.

Data shown is realistic: build 524 is today's git rev-list --count, areas and IDs follow the issue's TC-<AREA>-<NNN> scheme, and data files are the names you'd pick in Drive under My Drive\RepBunny QA\Test data\.

The open question is navigation. A splits the page into four tabs (Run, Journeys, Release, Data). B keeps everything on one scrolling page with a sticky header and collapsible areas. Everything else (test case layout, Report a bug, Clear all) is the same in both.

Option A: tabs

A1 · Run tab

Run setup on top: build, device, and what's installed (store bundle or personal). Every result saved records all three. Filter chips: Smoke (about 25, 30 min), Full, and Changed (areas whose code moved since their last pass). Changed areas sort first. Bars show pass, fail, blocked per area.

Opened from an area. Header facts: build type, priority, minutes, smoke tag. Preconditions name the exact Drive file. Every step and every UX check has a checkbox. Pass / Fail / Blocked plus notes. Last pass and last fail show their builds. Fail reveals Report a bug.
